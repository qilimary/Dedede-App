# “的地得”纠错 AI Pro（Dedede-App）

一款面向 Android 的本地中文纠错工具。当前版本 **3.7** 已将专业模式从旧版 RoFormerV2 更换为作者自研 **HCAM** 模型，并继续结合系统错词库、窄范围语法规则、白名单与置信度拦截，重点降低真实文本中的误改。

> 本 App 与 HCAM 模型均由“奇”制作与训练，免费使用。公众号：Li的信箱。

- 专业模型由旧 RoFormerV2 更换为 **HCAM E3-EMA 的/地/得专项模型**。
- Android 端专业推理由 **ExecuTorch 1.4.0** 运行。
- 专业模式默认参数重新校准为：
  - 温度：`1.0`
  - “的”阈值：`0.68`
  - “地”阈值：`0.68`

## 两种纠错模式

| 模式 | “的地得”检查 | 处理方式 | 适用场景 |
|---|---|---|---|
| 极速（不查“的地得”） | 不检查 | 不调用神经网络，仅运行系统错词库与规则 | 追求毫秒级速度，只检查其他错别字与语病 |
| 专业（HCAM） | 检查 | HCAM + 置信度拦截 + 白名单 + 窄范围安全规则 | 推荐日常使用，通常为秒级 |

极速模式下，专业参数会保留原值但置灰不可编辑；切回专业模式后继续使用原来的设置。

## HCAM 专业模型

当前 App 使用作者自研 HCAM 预训练基座进一步微调得到的 **E3-EMA 的/地/得三分类模型**。

Android 部署版本：

- 推理框架：ExecuTorch 1.4.0
- 运行后端：XNNPACK
- Tokenizer：18,000 字符级词表
- 输入：单个 `[1, L]` token 序列
- 输出：每个位置对应“的 / 地 / 得”三分类分数
- 模型文件大小：约 117.36 MiB
- 模型 SHA-256：`92a4faea70e1581bf95e00c8d56d3da349a4466d3aa542ef17fdefd773b562c9`

部署模型与 Tokenizer 在构建阶段会进行完整性校验，校验失败时构建会停止。

### 默认参数

| 参数 | 默认值 |
|---|---:|
| 温度 | `1.0` |
| “的”阈值 | `0.68` |
| “地”阈值 | `0.68` |
| “得”阈值 | `0.72` |

温度允许范围为 `0.5～2.0`。

`1.0` 表示直接使用模型原始 softmax 分布；低于 `1.0` 会让概率分布更尖锐、判断更激进，高于 `1.0` 会让概率分布更平缓、判断更保守。

只有模型预测出的目标字置信度达到对应阈值时，App 才会执行修改。

## 纠错流程

专业模式并不是让模型输出直接覆盖原文，而是结合多层保护：

1. 读取系统错词库与用户自定义规则；
2. 标记白名单、固定词、专名及明确合法结构；
3. 对需要判断的“的 / 地 / 得”位置运行 HCAM；
4. 按三个独立阈值拦截低置信度结果；
5. 应用范围受限的语法规则与上下文保护；
6. 生成可逐项查看、修改、还原和加入白名单的纠错结果。

设计目标是尽量避免为了提高召回率而使用过宽的“一刀切”规则。对于表面结构高度相似、语义上又可能合法的句子，宁可保留少量漏改，也不强行扩大规则造成现实文本误伤。

当前保护重点包括固定搭配、专有名词、植物名/地名、结果补语、方式状语、质地/性质结构、重复量词方式状语、小说口语及部分高歧义定语结构等。

## HCAM 专项测试

以下指标用于说明当前 HCAM 在“的 / 地 / 得”专项任务中的表现，不代表通用中文能力，也不等同于完整 App 在所有真实文本上的最终准确率。

| 测试集 | HCAM E3-EMA |
|---|---:|
| Mixed Total：720 句 / 2,275 个目标位，Macro-F1 | **98.17%** |
| External DEV：1,600 句 / 3,025 个目标位，Macro-F1 | **97.496%** |
| Natural DEV3：1,200 段 / 2,734 个目标位，Macro-F1 | **95.148%** |
| Natural DEV3：Macro-F0.5 | **95.882%** |
| Natural DEV3：clean false-action rate | **0.988%** |
| 500 段小说 / 4,486 个目标位，裸模型 Accuracy | **97.39%** |
| 7,152 个长尾/专名/固定词目标位，裸模型 Accuracy | **89.08%** |

500 段小说复测约 40,119 字，覆盖对白、动作、景物、心理、专名、地名、药名、叠词比喻、结果补语、方式状语和重复量词等结构。在当前保护体系下，该批测试没有发现新的“未被保护的高置信正确文本误改”。

不同测试集的分布差异较大，因此这些数字应视为专项回归与模型比较依据，而不是“任何文本都能达到同一准确率”的承诺。

## 主要功能

- **手动修改与还原**：纠错完成后，点击带下划线的字词，可采用修改、切换“的/地/得”或恢复原文。
- **直接加入白名单**：发现疑似错改时，可从纠错项直接进入白名单区域。
- **结果过期提示**：纠错完成后若修改原文，旧结果继续保留用于对照，同时显示醒目的过期提示；重新纠错后更新。
- **推理中断**：极速或专业模式正在检查时，如果继续编辑原文，会中断当前检查，避免旧任务覆盖新文本。
- **全屏输入编辑**：支持滚动条、撤销、还原和首行缩进，并与主输入框同步。
- **便签模式**：长按底部纠错结果区域进入全局编辑，可继续修改并导出。
- **快速跳转**：点击纠错清单中的序号，可跳到全文对应位置。
- **文件导入**：支持 TXT、MD、DOCX、PPTX、PDF 与各种图片格式，单次最多选择 20 个文件。
- **OCR**：图片可通过中文 ML Kit OCR 识别文字。
- **系统分享**：可从其他 App 选中文本后通过系统分享进入本 App。
- **自定义错词库**：
  - 只填写“原始文本”：作为白名单保护；
  - 同时填写“修改后”：建立自定义替换规则；
  - 用户自定义规则优先级高于系统规则。
- **历史记录**：最多保存最近 50 条。
- **悬浮窗**：支持后台快速纠错，并可同步回主界面继续操作。
- **标点清理**：检测到复制残留的异常标点时，可由用户确认后清理。
- **字体与皮肤**：支持正文字号、系统字号、界面皮肤与界面深浅调节。

## 模型与资源安全

构建时会对 HCAM、Tokenizer 与系统错词库进行 **AES-256-GCM** 加固。

每次构建都会生成新的主密钥、盐与 Nonce；运行时仅在 App 私有缓存目录中临时恢复模型供 ExecuTorch 加载，空闲释放后会尝试删除临时明文模型文件。

该机制主要用于提高资源直接提取的门槛，并不意味着客户端资源能够做到理论上的绝对不可提取。

## 使用提示

- 神经网络无法保证零误判，重要文本建议复核纠错清单。
- 白名单尽量填写完整词语或稳定短语，不建议大范围加入单字或过短片段。
- 单次纠错不建议超过约 30 万字；一次性粘贴超大文本、同时导入多个大文件，可能增加内存压力。
- 带复杂表格或特殊排版的 DOCX / PPTX / PDF 在提取文本后可能无法保留原排版。
- 不同手机的推理速度与内存占用会有差异。
- 专业纠错模型在设备本地运行，正文无需发送到在线大模型服务。
